Comprendre le Skill et l'Agent
ligne par ligne

Chaque élément du SKILL.md et du system prompt expliqué : son rôle, pourquoi il est écrit ainsi, ce qui change si on le supprime.

Niveau : Débutant à intermédiaire Durée de lecture : 20 à 30 min Prérequis : Avoir lu le tutoriel de base

0 Vue d'ensemble : deux fichiers, deux rôles

Avant de décortiquer chaque ligne, comprendre ce que fait chaque fichier et pourquoi ils sont séparés.

SKILL.md - Le "manuel de procédures"
  • Dit à Claude quoi faire et comment le faire
  • Contient les structures de documents
  • Donne le vocabulaire métier exact
  • Précise les règles légales applicables
  • Se déclenche automatiquement selon les mots-clés
  • Réutilisable dans n'importe quel contexte
System prompt - La "fiche de poste"
  • Dit à Claude qui il est dans ce contexte
  • Définit le ton et le style de communication
  • Fixe les limites (ce qu'il ne fait pas)
  • Précise le public cible et les relations
  • Reste actif toute la conversation
  • Spécifique au Projet Claude créé
Comment Claude lit ces deux fichiers avant de répondre
💡

A retenir : Le frontmatter décide si le skill est activé (déclencheur). Le corps du skill dit comment travailler (méthode). Le system prompt dit qui on est (identité). Claude combine les trois pour chaque réponse.

1 Le Frontmatter : le déclencheur automatique

Les premières lignes entre les "---" sont les plus importantes du fichier. C'est ici que Claude décide d'utiliser ou non le skill. Une mauvaise description = le skill ne se déclenche jamais.

SKILL.md — Frontmatter complet
---
name: doc-animateur-jeunesse

description: >
  Génère des documents professionnels
  pour les animateurs jeunesse et
  structures d'animation (ACM, centres
  sociaux, MJC, ALSH, collectivités,
  BAFA/BAFD).

  Utilise ce skill dès que la demande
  porte sur : fiche séance, projet
  d'animation, compte-rendu de réunion,
  rapport d'activité, bilan BAFA ou BAFD,
  projet pédagogique, fiche d'évaluation,
  note partenariale, planning d'animation,
  fiche incident ou comportement.

  Déclenche-toi aussi sur :
  "rédiger pour mon ACM",
  "bilan de stage animateur",
  "projet d'animation clé en mains",
  "compte-rendu réunion d'équipe",
  "rapport mensuel animateur",
  "fiche séance enfants",
  "projet péda ALSH".
---
Explication de chaque élément
  • NOM
    name: doc-animateur-jeunesse
    Identifiant technique du skill. Doit être unique, sans espaces, en minuscules avec tirets. Sert de référence si vous citez le skill dans d'autres fichiers.
  • PKQ
    description: >
    Le ">" indique un texte sur plusieurs lignes en YAML. Sans lui, la description serait coupée à la première ligne.
  • ROLE
    Première phrase : "Génère des documents..."
    Résume ce que fait le skill. Claude lit ceci en PREMIER pour savoir si le skill est pertinent. Commencer par un verbe d'action.
  • PKQ
    Liste des types de documents
    Chaque type listé est un mot-clé de déclenchement. Si l'utilisateur écrit "bilan BAFD", Claude reconnaît ce terme et active le skill.
  • ASTUCE
    "Déclenche-toi aussi sur..."
    Formulations en langage naturel que les utilisateurs emploient vraiment. Ces phrases dites "pushy" compensent la tendance de Claude à ne pas déclencher les skills.
  • RISQUE
    Si la description est trop courte
    Exemple mauvais : "description: Aide les animateurs". Claude ne déclenchera jamais ce skill, faute de mots-clés suffisants pour le reconnaître.

Règles d'or pour une bonne description

01
Commencer par un verbe d'action
Génère, Rédige, Produit, Aide à créer. Cela signale immédiatement ce que le skill accomplit concrètement.
02
Lister tous les cas d'usage
Chaque type de document ou de demande = un déclencheur potentiel. Plus la liste est riche, plus le skill se déclenche au bon moment.
03
Inclure le jargon métier
ACM, ALSH, BAFA, BAFD doivent être dans la description. Ce sont les mots que les utilisateurs tapent naturellement.
04
Ajouter des formulations naturelles
Les guillemets avec des phrases réelles ("fiche séance enfants") correspondent à ce que les utilisateurs écrivent, pas à un langage formel.
05
Être explicite sur le déclenchement
"Utilise ce skill dès que..." ou "Déclenche-toi aussi sur..." sont des instructions directes. Claude les suit mieux que des formulations passives.
06
Rester sous 200 mots
Le frontmatter est toujours en mémoire. Si il dépasse 200 mots, c'est qu'il contient des informations qui appartiennent plutôt au corps du skill.

2 Le Corps du SKILL.md : la méthode de travail

Une fois le skill déclenché, Claude lit le corps complet. Chaque section joue un rôle précis dans la qualité du document produit.

Section 1 : "Identifier le document demandé" (le filtre d'entrée)

SKILL.md — Section 1
## 1. Identifier le document demandé

Avant de rédiger, poser les questions
essentielles si elles ne sont pas données :

| Question | Pourquoi c'est important |
|---|---|
| Type de structure (ACM, MJC...) | Vocabulaire, cadre légal |
| Tranche d'âge du public | Objectifs adaptés |
| Thème ou intitulé | Nommer le document |
| Période concernée | Dates, durée |
| Destinataire du document | Directeur, familles... |
Explication
  • ROLE
    "Avant de rédiger, poser les questions si elles ne sont pas données"
    Cette phrase est une instruction conditionnelle. Claude pose des questions uniquement si le contexte manque. Si l'utilisateur a tout dit, il rédige directement sans demander.
  • PKQ
    Le tableau question / raison
    Le fait d'expliquer pourquoi chaque information est importante aide Claude à reformuler intelligemment la question selon le contexte. Il ne récite pas le tableau, il s'en inspire.
  • ASTUCE
    Limiter à 2-3 questions max
    Claude a tendance à poser trop de questions si on ne le cadre pas. La formulation "poser les questions essentielles" signal implicitement qu'il doit prioriser et ne pas tout demander.
  • EFFET
    Sans cette section
    Claude rédige immédiatement avec des hypothèses. Résultat : une fiche séance pour des inconnus, sans durée, sans matériel adapté. Inutilisable.

Section 2 : "Types de documents" (les gabarits)

SKILL.md — Exemple : Fiche séance
### A. Fiche séance / Projet d'activité

Structure obligatoire :
- Titre de l'activité
- Objectifs pédagogiques
  (2 à 4 max, verbes d'action)
- Public visé + effectif + âge
- Durée et lieu
- Matériel nécessaire
- Déroulement :
  accueil / mise en activité /
  temps fort / bilan
- Évaluation (mesure des objectifs)
- Animateur(s) référent(s)
Explication
  • ROLE
    "Structure obligatoire"
    Le mot "obligatoire" est important. Il demande à Claude de ne jamais omettre ces champs, même si l'utilisateur n'en parle pas. Sans ce mot, Claude peut "oublier" des sections.
  • PKQ
    "2 à 4 max, verbes d'action"
    Ces contraintes qualitatives sont cruciales. Sans elles, Claude écrit des objectifs vagues comme "sensibiliser à l'écologie" au lieu de "identifier 3 types de déchets recyclables".
  • ASTUCE
    Les phases de déroulement nommées
    "accueil / mise en activité / temps fort / bilan" est le découpage standard de l'animation jeunesse. Le nommer dans le skill garantit que Claude utilise le bon vocabulaire professionnel.
  • EFFET
    Si les gabarits sont absents
    Claude invente sa propre structure. Résultat : variable d'une génération à l'autre, non conforme aux attentes des directeurs ou des organismes de formation.

Section 2D : "Bilan BAFA" (le cas avec référentiel officiel)

SKILL.md — Bilan BAFA
### D. Bilan de stage BAFA / BAFD

Structure :
- Présentation du contexte
- Missions exercées
- Compétences développées
  (référentiel BAFA/BAFD)
- Situations significatives
  (2 à 3 exemples avec analyse)
- Auto-évaluation
- Conclusion et perspectives

Référentiel BAFA — 4 axes :
1. Vivre en collectivité
2. Animer et mettre en oeuvre
   un projet d'animation
3. Assurer la sécurité physique,
   morale et affective
4. Participer au fonctionnement
   et enrichir la vie de l'équipe
Explication
  • ROLE
    Les 4 axes du référentiel BAFA
    Ces axes sont officiels (DJEPVA). Les inscrire dans le skill empêche Claude d'inventer d'autres axes ou d'en oublier. Le bilan généré sera reconnu par les organismes de formation.
  • PKQ
    "Situations significatives (2 à 3)"
    La limite quantitative est intentionnelle. Sans elle, Claude en génère 6 ou 8, ce qui dépasse la taille attendue par les formateurs BAFA.
  • ASTUCE
    "avec analyse"
    Ce mot clé force Claude à ne pas seulement décrire les situations mais à les analyser (Qu'ai-je appris ? Comment j'aurais pu faire autrement ?). C'est la valeur ajoutée du bilan.
  • RISQUE
    Hallucination sur le légal
    Sans les axes officiels dans le skill, Claude peut "inventer" des axes plausibles mais faux. Un formateur BAFA les repérerait immédiatement.

Section 2H : "Fiche incident" (le cas sensible)

SKILL.md — Fiche incident
### H. Fiche incident / rapport de comportement

Structure :
- Date, heure, lieu
- Personnes impliquées
  (sans stigmatisation)
- Description factuelle des faits
  (sans interprétation)
- Actions immédiates prises
- Suite donnée
- Signatures

> IMPORTANT : Rester factuel.
> Éviter tout jugement de valeur.
> Mentionner si un signalement est
> nécessaire auprès de la direction.
Explication
  • LÉGAL
    "sans stigmatisation" et "sans interprétation"
    Ces deux consignes sont des garde-fous légaux. Une fiche incident avec des jugements ("l'enfant est violent par nature") peut être utilisée en procédure. Claude doit rester strictement factuel.
  • ROLE
    Le bloc "IMPORTANT" en citation
    La syntaxe ">" en Markdown crée une citation mise en évidence. Claude la traite comme une alerte prioritaire. Il applique ces instructions avec plus de rigueur qu'une instruction normale.
  • ASTUCE
    "Mentionner si un signalement est nécessaire"
    Claude ne décide pas à la place de l'animateur si un signalement s'impose. Il rappelle simplement la procédure. La décision reste humaine. C'est une limite éthique explicite.

Section 3 : "Mentions légales" (le cadre de conformité)

SKILL.md — Mentions légales
## 3. Mentions légales selon le contexte

| Contexte | Mention obligatoire |
|---|---|
| ACM | Déclaration DDETS obligatoire |
| BAFA/BAFD | Numéro de stagiaire si bilan
|   | transmis à l'organisme formateur |
| Données perso | Rappel RGPD si données
|   | nominatives (enfants, familles) |
| Fiche incident | Signalement CRIP possible si
|   | situation de danger pour un mineur |
Explication
  • PKQ
    Pourquoi un tableau "contexte / mention" ?
    Ce format oblige Claude à lier une mention légale à une situation spécifique. Il n'ajoute pas une mention RGPD à tous les documents, seulement aux cas pertinents.
  • ROLE
    Ces mentions réduisent les hallucinations juridiques
    Claude connaît le RGPD et la CRIP dans les grandes lignes. Le skill lui dit quand les citer et comment. Sans ça, il peut les citer à tort ou les omettre quand c'est nécessaire.
  • LIMITE
    Ce n'est pas un conseil juridique
    Ces mentions sont des rappels de cadre. Pour tout document engageant, un responsable juridique ou la direction vérifie. Le skill le précise d'ailleurs dans le system prompt de l'agent.

Sections 4 et 5 : Vocabulaire et consignes rédactionnelles

SKILL.md — Vocabulaire + Style
## 4. Vocabulaire professionnel

- ACM : Accueil Collectif de Mineurs
- ALSH : Accueil de Loisirs Sans
         Hébergement
- DDETS : Direction Départementale de
          l'Emploi, du Travail et des
          Solidarités
- Taux d'encadrement : 1/8 pour -6 ans,
                       1/12 pour +6 ans

## 5. Consignes rédactionnelles

- Écrire en français standard,
  sans jargon excessif
- Utiliser des verbes d'action
  pour les objectifs
- Une fiche séance ≤ 2 pages
- Un CR ≤ 1 page
- Toujours dater et signer les
  documents transmis à l'extérieur
Explication
  • ROLE
    Le glossaire intégré au skill
    Claude connaît ACM et ALSH de façon générale. En les définissant dans le skill, on garantit qu'il les utilise avec la bonne signification dans le contexte légal français (et non dans un contexte générique).
  • PKQ
    Le taux d'encadrement 1/8 et 1/12
    Ce sont des données légales précises (arrêté du 9 février 2007). Les inscrire dans le skill évite que Claude génère un autre ratio. Les erreurs sur ce point ont des conséquences réelles pour les structures.
  • ASTUCE
    "Fiche séance ≤ 2 pages, CR ≤ 1 page"
    Les contraintes de longueur sont souvent ignorées par Claude si on ne les précise pas. Il préfère naturellement des réponses longues et exhaustives. Ces limites cadrent le format professionnel attendu.
  • EFFET
    Sans le vocabulaire métier
    Claude peut utiliser "centre de vacances", "garderie" ou "colonie" à la place d'ACM ou ALSH. Ces termes inexacts fragilisent la crédibilité des documents produits auprès de professionnels.

Section 7 : "Exemples de test" (la validation intégrée)

SKILL.md — Tests intégrés
## 7. Exemple de test minimal

Prompt test 1 :
"Je dois rédiger une fiche séance
sur le recyclage pour des 8-12 ans,
durée 1h30, en ALSH."

Résultat attendu : Fiche complète avec
objectifs, matériel, déroulement
en phases et évaluation.

Prompt test 2 :
"Aide-moi à rédiger mon bilan BAFA,
j'ai travaillé 3 semaines dans un
séjour ados à la mer."

Résultat attendu : Questions avant
de rédiger, puis bilan sur 4 axes BAFA.
Explication
  • PKQ
    Pourquoi mettre des tests dans le SKILL.md ?
    Ces exemples servent de référence lors des itérations. Quand vous modifiez le skill, vous retestez avec les mêmes prompts pour vérifier que la qualité ne régresse pas. C'est votre "contrôle qualité" embarqué.
  • ASTUCE
    Varier les niveaux de contexte
    Le test 1 a toutes les infos. Le test 2 en manque (structure, missions réelles). Ainsi vous testez les deux comportements : rédiger directement ou poser des questions d'abord.
  • ROLE
    Ce que Claude en fait
    Claude ne "lit" pas ces tests comme des exemples à imiter. Ce sont vos repères à vous. Ils ne sont pas des exemples few-shot (ce serait trop lourd). Pour des exemples few-shot, utilisez les sections précédentes avec des cas concrets.

3 Le System Prompt de l'Agent : la fiche de poste

Le system prompt est lu à chaque début de conversation. Il reste actif tout au long de l'échange. C'est lui qui donne une "personnalité" à l'agent et fixe ses limites.

Bloc 1 : "Ton rôle" (l'identité professionnelle)

System Prompt — Rôle
# Agent IA - Assistant Rédaction
# Animateur Jeunesse

Tu es un assistant spécialisé pour
les animateurs et directeurs de
structures jeunesse en France.

## Ton rôle

Tu aides à rédiger :
- fiches séance
- projets d'animation
- comptes-rendus de réunion
- rapports d'activité
- bilans BAFA / BAFD
- projets pédagogiques
- notes partenariales
- fiches incident
Explication
  • ROLE
    "Tu es un assistant spécialisé..."
    Cette formulation en "tu es" est délibérée. Elle donne à Claude une identité stable. Il reste dans ce rôle même si l'utilisateur dévie vers d'autres sujets. C'est plus efficace que "aide les animateurs à...".
  • PKQ
    "en France"
    Deux mots qui changent tout. Sans eux, Claude peut répondre avec le cadre légal belge ou suisse (où BAFA n'existe pas). En France = Code de l'action sociale, DDETS, DJEPVA, référentiel BAFA français.
  • ASTUCE
    La liste des documents dans le rôle
    La répéter ici (même si elle est dans le skill) renforce la cohérence. L'agent sait lui-même ce qu'il produit, indépendamment du skill. Si le skill ne se déclenche pas, l'agent reste capable de vous orienter.

Bloc 2 : "Ton style" (comment il communique)

System Prompt — Style
## Ton style de communication

- Ton chaleureux,
  professionnel,
  encourageant
- Langage clair, sans jargon inutile
- Si tu utilises un terme technique
  (DDETS, CRIP...),
  explique-le brièvement
- Jamais condescendant : ces
  professionnels savent ce qu'ils
  font sur le terrain
Explication
  • ROLE
    "Chaleureux, professionnel, encourageant"
    Ces trois adjectifs définissent l'équilibre de ton. "Chaleureux" seul = trop familier. "Professionnel" seul = trop froid. Ensemble, ils créent le registre adapté aux animateurs, souvent jeunes et en apprentissage.
  • PKQ
    "Expliquer les termes techniques"
    Les animateurs stagiaires connaissent peu les acronymes administratifs (DDETS, CRIP...). Cette instruction empêche Claude d'utiliser le jargon sans l'expliquer, ce qui rendrait les réponses inaccessibles.
  • ATTENTION
    "Jamais condescendant"
    Sans cette instruction, Claude peut adopter un ton pédagogique excessif qui infantilise des professionnels expérimentés. "Ces professionnels savent ce qu'ils font sur le terrain" lui rappelle le contexte d'expertise pratique de ses utilisateurs.

Bloc 3 : "Comment tu travailles" (le process en 4 étapes)

System Prompt — Process
## Comment tu travailles

1. Quand une demande arrive,
   identifie d'abord le type de
   document demandé.

2. Si des informations clés manquent
   (public, durée, thème, structure...),
   pose 2 ou 3 questions ciblées
   AVANT de rédiger. Pas plus.

3. Génère le document dans un format
   structuré, clair, prêt à copier-coller
   ou à mettre en page.

4. En fin de document, propose
   une liste "points à vérifier
   avant diffusion".
Explication
  • ROLE
    Étape 1 : Identifier le type
    Claude peut recevoir une demande vague ("aide-moi à écrire quelque chose pour la réunion"). Cette étape l'oblige à clarifier mentalement le type de document avant d'agir. Cela améliore la pertinence de la sortie.
  • CLÉ
    Étape 2 : "AVANT de rédiger" en majuscules
    Les majuscules sont intentionnelles. Claude a une forte tendance à rédiger immédiatement pour "être utile". Le mot "AVANT" en majuscules brise ce réflexe. Sans ça, il rédige avec des hypothèses erronées.
  • ASTUCE
    "Pas plus" après "2 ou 3 questions"
    Deux mots qui réduisent une frustration fréquente. Sans eux, Claude pose 6 à 8 questions. L'utilisateur abandonne. "Pas plus" = maximum 3 questions prioritaires, puis on rédige.
  • ROLE
    Étape 4 : "Points à vérifier avant diffusion"
    Cette section finale protège l'animateur. Elle lui rappelle ce qu'il doit vérifier manuellement : dates, noms, conformité légale locale. L'IA produit, l'humain valide.

Bloc 4 : "Ce que tu NE fais PAS" (les limites explicites)

System Prompt — Limites
## Ce que tu NE fais PAS

- Tu ne rédiges pas de signalement
  officiel (IP, CRIP) à la place de
  l'animateur : tu guides, tu expliques
  la procédure, mais la décision et la
  signature restent humaines.

- Tu ne fournis pas de conseils
  médicaux ou juridiques au-delà de
  tes compétences.

- Tu ne génères pas de données
  personnelles fictives sur de vrais
  enfants.
Explication
  • LÉGAL
    Le signalement IP / CRIP
    Un signalement mal rédigé peut avoir des conséquences légales pour l'animateur et la structure. En interdisant à Claude de le faire seul, on protège les utilisateurs. L'agent peut expliquer la procédure, jamais la remplacer.
  • PKQ
    "la décision et la signature restent humaines"
    Cette formulation est pédagogique autant que technique. Elle rappelle à l'utilisateur son rôle et sa responsabilité. L'IA est un outil, pas un substitut de décision.
  • RGPD
    "Ne pas générer de données nominatives réelles"
    Si un animateur écrit "l'enfant Théodore Dupont, né le 12/03/2018..." dans l'invite, Claude ne doit pas réutiliser ces données dans des exemples ou des documents fictifs. C'est une limite RGPD explicite.
  • ASTUCE
    Commencer par "Tu NE fais PAS"
    Énoncer les limites en positif (ce que l'agent fait) n'est pas suffisant. Les interdits formulés explicitement ("tu ne rédiges pas") sont mieux respectés par Claude que des formulations implicites.

Bloc 5 : "Cadre légal" (les références réglementaires)

System Prompt — Légal
## Cadre légal de référence

- Code de l'action sociale et
  des familles (CASF) - ACM
- Arrêté du 9 février 2007
  (encadrement des mineurs)
- Référentiel BAFA/BAFD (DJEPVA)
- RGPD pour les données nominatives
- Protocole de signalement :
  IP → CRIP → Procureur si danger
  immédiat
Explication
  • ROLE
    Citer les textes de loi par leur nom exact
    Le "Code de l'action sociale et des familles" et l'"arrêté du 9 février 2007" sont les vraies références. Les inscrire réduit les hallucinations légales. Claude est moins susceptible d'inventer d'autres références.
  • PKQ
    La chaîne de signalement "IP → CRIP → Procureur"
    Ce n'est pas un détail. C'est la procédure légale française. En la formalisant dans le system prompt, Claude peut l'expliquer correctement à un animateur qui ne la connaît pas, sans l'inventer.
  • LIMITE
    Ce que ça ne couvre pas
    Les textes évoluent. Un arrêté peut être modifié. Ce cadre est celui de mai 2025. Prévoir une révision annuelle du system prompt pour vérifier que les références restent valides.

Bloc 6 : "Exemple de démarrage" (le comportement par défaut)

System Prompt — Exemple
## Exemple de démarrage

Si l'animateur écrit :
"Je dois faire ma fiche séance
 de demain"

Tu réponds :
"Super, je t'aide ! Pour que la
fiche soit utile, dis-moi :
- quel thème ou activité ?
- pour quel âge et combien
  d'enfants ?
- combien de temps ?"

Puis tu génères la fiche complète
dès que tu as ces éléments.
Explication
  • ROLE
    Un exemple concret dans le system prompt
    C'est du "few-shot prompting" intégré. En montrant à Claude un échange type, on lui donne un modèle de comportement. Il reproduit ce style d'interaction sans avoir besoin d'une longue description.
  • ASTUCE
    "Super, je t'aide !"
    Ce ton décontracté et encourageant est intentionnel. Il tranche avec un Claude trop formel qui écrirait "Bien entendu, je vais vous aider à rédiger ce document." L'exemple définit le registre de façon plus efficace que dix adjectifs.
  • PKQ
    "Puis tu génères dès que tu as ces éléments"
    Cette instruction ferme la boucle. Sans elle, Claude peut poser une quatrième question ou redemander confirmation. Ici, 3 réponses = on rédige. Pas de délai supplémentaire.

4 Interaction Skill + Agent : qui fait quoi ?

Les deux fichiers travaillent ensemble mais ne font pas la même chose. Voici comment ils se complètent et comment ils se "parlent" sans se contredire.

Situation concrète SKILL.md intervient System prompt intervient
L'animateur demande une fiche séance Fournit la structure exacte (phases, objectifs en verbes d'action, matériel...) Fixe le ton chaleureux, demande 2-3 infos si elles manquent
La demande est vague ("aide-moi à écrire quelque chose") Pas encore activé - manque de mots-clés Pose des questions pour identifier le type de document voulu
Mention d'une fiche incident Donne la structure factuelle et le bloc IMPORTANT sur le jugement de valeur Rappelle de ne pas rédiger un signalement officiel à la place de l'animateur
L'animateur utilise un terme ambigu ("rapport") Liste 3 types de rapports possibles avec leurs structures Demande à l'animateur lequel il veut, avec un ton direct et simple
Demande hors périmètre (ex : droit du travail) Pas de section concernée = ne s'active pas Reconnaît la limite et renvoie vers les ressources compétentes
⚠️

Point de vigilance : Si le skill et le system prompt se contredisent (ex : le skill dit "toujours proposer un format Word" mais le system prompt dit "rédiger uniquement en Markdown"), Claude choisit généralement le system prompt car il a la priorité contextuelle. Harmonisez les deux fichiers à chaque modification.

  • Les contraintes de longueur par document
